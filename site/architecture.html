Layered Architecture

The simulation engine has zero UI dependency and is fully testable headless. The UI only reads immutable snapshots and submits timestamped commands. One canonical serializer powers save/load, the black-box replay recorder and the benchmark checksum.

Launch & render loop

  • electron/main.js is the desktop launch entry point: it opens index.html from local files (file://) with no network access and a 1024 px minimum window width.
  • A small classic (non-module) boot guard in index.html loads first and installs error/rejection/timeout handlers. If the ES-module console never signals a successful boot — an ES-module-incapable runtime, a failed module fetch, or an init error — it reveals a readable fallback panel rather than leaving a blank/"crashed" window. This is the offline-Electron equivalent of the brief's "degrade to a readable error message if the UI toolkit is unavailable" requirement.
  • The render loop uses requestAnimationFrame purely to read snapshots; the engine advances on its own SimClock accumulator, so frame rate never affects simulation results.

Per-tick ordering (deterministic)

  1. apply commands scheduled at this tick (insertion order)
  2. fire scenario events scheduled at this tick
  3. solve the power network (priority + capacity)
  4. apply continuous failure consequences (+ seeded spawns)
  5. oxygen: generate / consume / leak / diffuse / crew health
  6. thermal: reactor heat balance / droop / shutdown / damage
  7. drones: physical travel + task execution + re-planning
  8. evaluate end conditions, then increment the tick counter

Determinism & Persistence Model

  • All simulation-affecting quantities are integers or fixed-point scaled integers (oxygen 0..capacity, temperature ×10, drone progress ×1000). No floats enter the sim state.
  • The engine advances only in whole 100 ms integer ticks.
  • The accumulator loop converts real elapsed time × speed into a whole number of ticks — 60 s at 1x and 8x reach identical state.
  • Randomness comes from one seeded RNG; failures are generated only from it, so seed + command list fully determine every future state.
  • The canonical serializer emits sorted-key, order-independent JSON of the entire snapshot (modules, connections, drones, task queues, active repairs, failures, sim-time, RNG getState and event log) plus the command history, sealed with a SHA-256 integrity digest. Load recomputes the digest and validates the schema/version, rejecting corrupt or incompatible data as a typed error — never a crash.
  • Engine.fromSnapshot() restores that state verbatim (RNG position, scenario-event flags, tick, event log), so continuing a loaded save is indistinguishable from never having closed the app.
  • The black box stores the seed, initial config and every timestamped command; the replay driver re-runs the engine to the identical final checksum.
  • A stable FNV-1a checksum over the sorted snapshot yields identical values for identical runs (used by tests, replay verification and the benchmark).
